# BioLexicon

バイオインフォマティクス・創薬・ヘルステック領域で働くソフトウェアエンジニアは、論文中の生物学専門用語に遭遇するたびに作業が中断し、概念間の依存関係を把握できないまま調べ物が膨張するという慢性的な非効率を抱えている。BioLexicon は、生物学用語をエンジニアの思考モデル（オブジェクト指向・状態遷移など）に翻訳した検索可能な辞典と、概念間の依存関係を可視化するインタラクティブグラフ、個人ナレッジベース機能を組み合わせ、3分以内に用語の意味と関連概念ネットワークを把握して論文読解に復帰できる環境を提供する。

---

## 主要機能

- **エンジニア向け生物学用語辞典**
  - 前方一致・部分一致・英日両言語・同義語（例: CDK / cyclin-dependent kinase）に対応した高速検索（1秒以内）
  - 各用語に「エンジニア向け比喩」「正式定義」「関連用語リンク」「頻出コンテキスト」の4フィールドを付与
  - 初期シードデータとして細胞生物学用語 200件以上・リレーション 50件以上を収録

- **概念ネットワークグラフ**
  - Cytoscape.js によるインタラクティブなノード＝用語・エッジ＝関係種別（活性化・抑制・構成要素・前提知識）の可視化
  - ノードクリックで用語詳細と隣接ノードのハイライトを表示
  - 500ノード超はクラスタリングで初期表示を最適化、WebGL 非対応環境ではリスト表示にフォールバック

- **コンテキスト検索（論文用語ルックアップ）**
  - 論文テキスト（最大 2,000 文字）を貼り付けると、DB 内用語リストとのサーバーサイド正規表現マッチングで生物学専門用語を自動検出（5秒以内）
  - 検出用語はクリッカブルで辞典詳細ページへ遷移、未登録用語は登録リクエストへ誘導

- **個人ナレッジベース（マイノート）**
  - 用語閲覧時に自動で閲覧履歴を DB に記録
  - 自由テキストメモ（最大 5,000 文字）とタグ（最大 10 個）を PostgreSQL に永続保存
  - CommonMark 準拠の Markdown ファイルをインポートして既存用語エントリと自動マッチング

- **学習パス推薦**
  - 閲覧履歴（5件以上で起動）と概念グラフの依存関係から、次に学ぶべき前提用語を理由付きで最大 10件推薦

│   │   ├── api/              # バックエンド API クライアント
│   │   └── main.tsx
│   ├── Dockerfile
│   └── package.json

```

| ファイル / ディレクトリ | 説明 |
|---|---|
| `AGENT.md` | AI エージェントが守るべきコーディング規約・制約・テスト方針 |
| `Plan.md` | 機能ごとの実装フェーズ・完了条件・依存関係 |
| `docker-compose.yml` | ローカル環境の一括起動定義（api / db / frontend） |

## AI コーディングエージェントでの使い方

本リポジトリは [Cursor](https://cursor.sh/) / [GitHub Copilot Workspace](https://githubnext.com/projects/copilot-workspace) / [Claude](https://claude.ai/) などの AI コーディングエージェントでの利用を想定して設計されています。

### 1. `AGENT.md` を最初に読み込む

エージェントのコンテキストに `AGENT.md` を渡し、以下のルールを必ず遵守させてください。

- **モックデータ・ハードコード配列・スタブ API の使用禁止**（本物の DB / API 接続のみ）
- **バックエンドファーストで実装**（UI より先に API エンドポイントを完成させる）
- 未実装機能は UI 上で明示的に `"未実装"` と表示し、モックで補完しない
- 全 API に `X-API-Key` ヘッダー認証を実装し、ユーザー固有データ API には JWT Bearer Token を必須とする

### 2. `Plan.md` でタスクを確認する

`Plan.md` には実装フェーズとタスクが優先順位付きで列挙されています。

```
Phase 1: DB・マイグレーション・シードデータ
Phase 2: 用語検索 API + コンテキスト検索 API
Phase 3: 概念グラフ API
Phase 4: マイノート API（認証付き）
Phase 5: 学習パス推薦 API
Phase 6: フロントエンド 4画面の実装
Phase 7: テスト・パフォーマンス
